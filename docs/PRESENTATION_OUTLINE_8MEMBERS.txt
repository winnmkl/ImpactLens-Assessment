------------------------------------------------------------------------------
Title: What Is ImpactLens?

Bullet points:
  - Web-based IAR and risk assessment platform (v2.0)
  - Three roles: Standard User, Info Sec, Admin (CISO)
  - Three-tier asset workflow: Draft -> Pending Approval -> Approved
  - Live risk math: inherent + residual + mandatory control floors
  - 13 security controls mapped to major frameworks
  - Excel audit export (7-10 sheets) + system logs + notifications

Optional visual: Simple 3-box diagram (User | Info Sec | CISO)

SLIDE 4 - ARCHITECTURE (Member 3) | ~1.5 minutes
------------------------------------------------------------------------------
Title: System Architecture

Bullet points:
  - Frontend: HTML, CSS, Vanilla JavaScript (no React - lightweight)
  - Backend: Supabase (PostgreSQL + Auth + Row Level Security)
  - Tables: Assets, AssetControls, user_profiles, SystemLogs, ReportData
  - Security: JWT login, RLS at database, role-based UI hiding
  - Hosted locally: npm start -> http://localhost:8000

Visual: Simple diagram
  [Browser] --HTTPS/JWT--> [Supabase Cloud: Auth + Database]

Speaker 3 says:
  - Explain why Supabase (auth, real-time sync, RLS without custom server)
  - One sentence: "UI checks role, database also enforces role - defense in depth"

SLIDE 8 - RISK CALCULATION PART 1 (Member 6) | ~1 minute
------------------------------------------------------------------------------
Title: How Risk Is Calculated (Inherent)

Bullet points:
  - CIA scoring: Confidentiality + Integrity + Availability (3-9)
  - Classification: Public, Internal, Confidential, Restricted
  - User sets Probability (1-5) and Severity (1-5)
  - Inherent escalations (NIST SP 800-30 style):
      * Internet-facing + external cyber threat -> higher P
      * PII/SPI + data leak -> S = 5
      * Restricted data + cyber/insider -> S >= 4
      * Financial asset (FA) + cyber -> S = 5
  - 5x5 matrix -> Inherent rating (Very Low to High)

Visual: Small 5x5 heatmap or color legend (red/amber/cyan/green)

Speaker 6 says:
  - Focus on "before controls" - what could go wrong at worst case

------------------------------------------------------------------------------
SLIDE 9 - RISK CALCULATION PART 2 (Member 6) | ~1 minute
------------------------------------------------------------------------------
Title: Residual Risk, Controls & Floors

Bullet points:
  - 13 controls (MFA, RBAC, Encryption, Backup, EDR, Firewall, etc.)
  - Only threat-relevant controls reduce P/S (weighted + synergy bonuses)
  - Diminishing returns: cannot game the system with too many checkboxes
  - Mandatory floors: missing baseline controls -> residual cannot go below floor
      * Restricted data -> floor Moderate
      * Financial asset (PCI) -> floor High
      * PII/SPI -> floor Moderate (RA 10173)
  - Cannot "Accept" High residual risk (ISO 27001 risk appetite)

Speaker 6 says:
  - One sentence example: "Without MFA on restricted data, residual stays Moderate
    even if other controls are checked"
